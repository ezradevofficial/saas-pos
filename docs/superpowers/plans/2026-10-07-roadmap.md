# Delivery Roadmap

> **For agentic workers:** this is the master sequence. Each phase gets its own detailed plan in `docs/superpowers/plans/` written when the phase starts, against the code as it then exists. Execute phases in order; never start a phase whose predecessor's exit criteria are not met.

**Goal:** Deliver the multi-tenant POS and business platform described in `docs/concept-note.md` and `docs/platform-core-spec.md`, in the build order of concept note section 10, each layer tested before the next depends on it.

**Sources:** `CLAUDE.md` (working rules), `docs/platform-core-spec.md` (requirement IDs), `docs/concept-note.md` (scope, pricing, decisions), `design/system/` (design system README, tokens, 18 component specs and reference bundle), `design/screens/` (11 screen designs as `.dc.html`).

## Global constraints (every phase)

- No product name anywhere; display name from `APP_NAME` and the `app.name` translation key.
- Ports: web 3008, API 8008 (strict).
- Branch → code + tests → merge to `main` → push → pull. Never commit straight to `main`.
- Tests written with the code; run only the touched tests locally; CI runs everything.
- Every UI change verified with the Playwright MCP on port 3008 (screenshot + console check).
- English and French only; every string in translation files.
- Money as `bigint` minor units + ISO currency; rates `numeric(18,8)`; UUID v7 keys; UTC timestamps.
- Every tenant table: `tenant_id uuid not null`, indexed, RLS forced, isolation test.
- Styling only from tokens; no Tailwind palette or arbitrary values.

## Cross-phase rules

- Business modules never read another module's tables; they use domain events and core services.
- Tax and payroll rates come only from country-pack data rows. Where the data is unknown, ship the table and the loader with an empty or clearly flagged dataset and list the gap in the phase report; never invent figures.
- External integrations (Daraja, eTIMS, DGI, aggregators, SMS, email) sit behind an adapter interface with a fake driver used in tests and local development; real drivers need credentials the owner provides.
- Deploying to Linode needs credentials the owner provides; CI ships the workflow with deploy jobs gated on those secrets existing.
